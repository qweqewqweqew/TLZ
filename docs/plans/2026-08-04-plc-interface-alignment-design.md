# PLC 接口文档对齐设计

## 目标

以《交换接口文档-电气 V2.2（20260624）》为准，对齐前端 PLC 状态显示和 ROS 消息映射，不改变已经一致的控制字、路径字段与进给方向定义。

## 对照结论

- PLC 状态字需要在界面显示为业务文本：0 无、1 系统急停、2 准备就绪、3 系统故障、4 拍照完成、12 任务执行中、30 路径请求、40 拍照请求、50 换刀中、60 换刀完成。
- `PlcPathParams.msg` 的数据字段正确，但注释中的反馈路径参数起始地址应为 DB 68.0，而不是 DB 66.0。
- 前端 `PlcPathParamsVM` 漏掉反馈区的 2 个整型和 2 个实型预留字段。
- 前端 `PlcPathCommandParamsVM` 漏掉写入区的 3 个整型和 4 个实型预留字段。
- 控制字、路径总数、当前路径、故障码，以及进给方向 10/20/30/40 的定义已经与文档一致，不作修改。

## 实现

1. 在设备状态区域按状态字显示 PLC 中文状态；故障码非零时优先显示“系统故障”，并在提示信息中保留原始状态字和故障码。
2. 补齐两个前端 ViewModel 的预留字段，并在 `Ros2Bridge` 中逐字段转换，确保 ROS 消息没有被截断。
3. 修正 ROS 消息的 DB 地址注释，不改变消息字段顺序和通信类型，因此不影响现有消息二进制布局。

## 验证标准

- 前端 Release 目标能够成功增量构建。
- ROS 接口包能够成功构建。
- 打包目录更新后，`MzTLZ.exe` 可以直接启动。
- Git 暂存和提交中不包含用户已有的其他未提交修改。
